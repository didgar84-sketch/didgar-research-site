# راهنمای نسخۀ نهایی سایت مؤسسۀ پژوهشی دکتر دیدگر

نسخۀ ۲.۱.۰؛ اصلاحات درخواست جاری روی سایت سه‌زبانۀ پیوست اعمال شده‌اند. بسته شامل ۱۲۶ صفحۀ مستقل، ۲۸ راهنما در هر زبان، شش صفحۀ خدمت در هر زبان، ۳۴ منبع پژوهشی و جعبه‌ابزار پژوهش است.

## فایل‌های تحویلی

- `didgar-vercel-package-final.zip`: بستۀ کامل برای ویرایش و انتشار؛ پوشۀ `didgar-site` و فایل HTML مستقل را در ریشۀ آرشیو دارد.
- `didgar-preview.html`: نسخۀ مستقل همۀ صفحات؛ فونت‌ها، تصویرها، CSS، JavaScript و الگوهای قابل دریافت در همین فایل جاسازی شده‌اند.
- `didgar-site/SEO-AUDIT-FA.md`: گزارش بررسی، اصلاحات، نتایج واقعی آزمون‌ها و حدود تأیید.

برای دیدن نسخۀ مستقل، فایل HTML را با مرورگر باز کنید. تغییر زبان و صفحه، جست‌وجو و ابزارها با JavaScript کار می‌کنند. تصویرها و فونت‌ها برای نمایش به اینترنت نیاز ندارند؛ بازکردن منابع بیرونی و پیام‌رسان‌ها به اینترنت نیاز دارد.

## تغییرات ظاهری و ارتباطی

بخش بزرگ پاورقی در تصویر پیوست، در همۀ صفحات حذف شده است. لینک‌های Telegram و Instagram آن بخش هم حذف شده‌اند. پنج راه ارتباط در بخش تماس صفحۀ اصلی دیده می‌شوند: WhatsApp، Telegram، تلفن، Instagram و ایتا. در هر دکمه، نماد زیر نام قرار دارد. شمارۀ تلفن و مقصدهای واتساپ، تلگرام و اینستاگرام همان اطلاعات ارسالی شما هستند.

لینک حساب اختصاصی ایتا در ورودی ارائه نشده است؛ دکمۀ ایتا به `https://eitaa.com/` متصل است و زیر آن «وب‌سایت رسمی ایتا» نوشته شده است. نماد ایتا، نشان رسمی دریافت‌شده از وب‌سایت ایتاست. پس از مشخص‌شدن حساب مؤسسه، مقدار `contacts.eitaa_url` در فایل `content/site-content.json` را به لینک درست تغییر دهید و سایت را دوباره تولید کنید. مقصد باید HTTPS و روی دامنه ایتا باشد.

عبارت برند کنار لوگو بزرگ‌تر شده است؛ در موبایل فضای کامل یک ردیف به آن اختصاص می‌یابد. نوار شعار و نوار نام نرم‌افزارها حذف شده‌اند. زیرنویس‌های تصاویر حذف شده‌اند. دسترسی به حریم خصوصی، شرایط همکاری و سیاست محتوایی، داخل بخش فرم تماس حفظ شده است.

فونت فارسی Vazirmatn و فونت عربی Cairo است. انتخاب فونت هم برای زبان اصلی صفحه و هم برای متن‌هایی که `lang="fa"` یا `lang="ar"` دارند اعمال می‌شود؛ بنابراین عبارت «العربية» در صفحۀ فارسی نیز با Cairo نمایش داده می‌شود. فایل‌های متغیر WOFF2 و مجوزهای OFL در بسته هستند.

## انتشار روی Vercel

فایل ZIP را باز کنید و پوشۀ `didgar-site` را به عنوان ریشۀ پروژه انتخاب کنید. تنظیمات آماده‌اند:

| تنظیم | مقدار |
|---|---|
| Framework | Other |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js | ۲۰ یا جدیدتر |

ساخت معمول سایت فقط به Node نیاز دارد. فایل‌های HTML و دارایی‌ها از پیش تولید شده‌اند. Python برای ویرایش و بازتولید محتوا و آزمون‌های نگهداری استفاده می‌شود.

نشانی مبنا در فایل‌های منبع `https://dr17.vercel.app` است. هنگام Build، `SITE_URL` یا دامنه production اعلام‌شده توسط Vercel، در canonical، hreflang، sitemap و داده‌های ساختاریافته جایگزین می‌شود. برای دامنه اختصاصی، `SITE_URL` را به شکل یک مبدأ HTTPS بدون مسیر، query یا fragment تنظیم کنید؛ مانند `https://example.org`. نشانی یک Preview نباید جای دامنه اصلی سئو قرار بگیرد.

نسخۀ production نمایه‌پذیر است. استقرارهای Preview دارای `noindex` هستند. فایل HTML مستقل نیز `noindex` دارد و برای مشاهده و انتقال ساده طراحی شده است؛ برای انتشار اصلی و داشتن URL مجزای صفحات، از خروجی `dist` استفاده کنید.

## اجرای محلی و نگهداری

```sh
npm run build
npm run dev
```

سایت در `http://127.0.0.1:3000` باز می‌شود. بازکردن مستقیم `index.html` چندصفحه‌ای با دوبار کلیک، مسیرهای ریشه‌دار دارایی‌ها را شبیه یک سرور وب حل نمی‌کند؛ برای دوبار کلیک از `didgar-preview.html` استفاده کنید.

منبع اصلی محتوا، عنوان‌ها، توضیح‌ها، تصاویر موضوعی، دسته‌بندی‌ها، منابع و ارتباط موضوعی راهنماها، `content/site-content.json` است. تغییر مستقیم HTML تولیدشده با اجرای مولد بازنویسی می‌شود.

```sh
python3 -m pip install -r requirements-maintenance.txt
npm run generate
npm run build
npm run standalone
npm test
npm run test:seo
npm run test:interactions
npm run test:standalone
npm run test:release
npm run test:build
npm run test:http
```

برای آزمون HTTP، سرور محلی را باز نگه دارید و در ترمینال دوم `TEST_ORIGIN=http://127.0.0.1:3000 npm run test:http` را اجرا کنید. برای آزمون بصری در دستگاهی که Playwright و Chromium دارد، با همین مبدأ `npm run test:browser` را اجرا کنید.

## فرم، حریم خصوصی و ابزارها

فرم، خلاصۀ درخواست و پیوند واتساپ را آماده می‌کند. ارسال نهایی با اقدام شخص در واتساپ انجام می‌شود. برنامه پایگاه داده یا صندوق ذخیرۀ درخواست ندارد. اعتبارسنجی آنلاین و آفلاین شامل طول متن، فضای خالی، تاریخ، رضایت و فیلد ضد هرزنامه است. وقتی JavaScript غیرفعال است، لینک مستقیم واتساپ نمایش داده می‌شود و کنترل‌های وابسته به JavaScript پنهان‌اند. روش POST فرم از تبدیل اطلاعات به query نشانی صفحه جلوگیری می‌کند.

ابزار DOI فقط پیوند استاندارد می‌سازد؛ وجود یا صحت علمی مدرک را تأیید نمی‌کند. برنامه‌ریز زمان، تقسیم اولیه برای تنظیم با شرایط واقعی پژوهش ارائه می‌کند. الگوهای Markdown در هر سه زبان قابل دریافت و ویرایش‌اند.

## وضعیت بررسی

آزمون‌های خودکار ساختار، سئو، HTTP، داده‌های ساختاریافته، فرم، جست‌وجو، DOI، برنامه‌ریز و نسخۀ مستقل موفق بوده‌اند. گزارش‌های واقعی در `reference/qa` هستند.

رندر بصری مرورگر در این محیط تأیید نشد: مرورگر محلی فراهم نشد؛ دسترسی مرورگر ابری به نشانی محلی مسدود بود و بازکردن فایل محلی نیز به دلیل سیاست امنیتی مرورگر مجاز نبود. از این رو نمرۀ Lighthouse، اندازه‌گیری LCP/INP/CLS، نبود همۀ ایرادهای ظاهری در دستگاه‌های واقعی، وضعیت نمایه‌سازی و رتبه در گوگل ادعا نشده‌اند. ساختار واکنش‌گرا و کنتراست رنگ‌های اصلی از روی کد بررسی شده‌اند.

پس از انتشار، صفحه‌های اصلی و نمونه‌ای از هر زبان را با URL Inspection، Rich Results Test و PageSpeed Insights بررسی کنید و `/sitemap.xml` را در Search Console ثبت کنید. مالک دامنه می‌تواند توکن تأیید را در `GOOGLE_SITE_VERIFICATION` تنظیم کند و دوباره Build بگیرد.
